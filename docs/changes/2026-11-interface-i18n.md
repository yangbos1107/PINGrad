- CON-I18N-002：Docusaurus 固定到 3.10.2，沿用 React 18、本地搜索及现有提交接口。
- CON-I18N-003：学校经验、录取数据、关于页正文不翻译；只维护一份正文。
- ASM-I18N-001：中文默认路径不变，英文使用原生 `/en/` 前缀；语言切换使用 Docusaurus 自带菜单。
- OOS-I18N-001：不修改 Teable 数据或部署配置，不真实提交测试记录；嵌入应用语言取决于其自身支持。

## 方案与接口

ADR-I18N-001：用户已选择原生 Docusaurus i18n，而非同地址的自定义运行时语言状态。默认 `zh-Hans`、第二语言 `en`；正文通过原生源文件回退共用，只新增界面翻译 JSON。代价是分别构建两个 locale；收益是复用框架导航、主题翻译及语言菜单。

- MOD-I18N-001：配置和原生翻译 JSON 负责 navbar/footer/sidebar 与框架语言；定制 UI 使用 `Translate` / `translate`。
- MOD-I18N-002：目录沿用文档元数据生成，输出当前语言的 permalink；项目名和分组排序保持原样。
- MOD-I18N-003：独立关于页共用一份 MDX，外层 Layout 与标题可翻译，中文正文标注 `lang="zh-CN"`；兼容页不进索引。
- IF-I18N-001 / IN-I18N-001：locale 为 `zh-Hans` 或 `en`，路径及 hash 为输入；中文 `/intro` 对应英文 `/en/intro`，未知页面使用原生 404。
- IF-I18N-001 / OUT-I18N-001：界面字符串按 locale 输出，缺失正文翻译回退原始文件，不使用机器翻译。
- IF-I18N-002：投稿仍 `POST https://api.pingrad.app/submit-dp`，字段名、枚举值、日期和自由文本协议保持不变；只本地验证，不发送记录。
- MOD-I18N-004：先验证普通构建，再评估 Faster；只有兼容性和构建收益得到验证才启用。站点存储隔离沿用官方稳定配置。
- MOD-I18N-005：包装主题按钮，在其左边复用原生 `LocaleDropdownNavbarItem`；图标、语言名称、箭头、URL 与菜单均沿用框架，桌面与手机菜单同源。

## 构建与修复记录

- 3.10.2 普通构建通过；初次 `faster: true` 因 SSG worker threads 需要 v4 flag 而拒绝配置。改为逐项开启稳定加速项，保留 v3 渲染语义。
- 一次本地连续双语构建计时：普通构建 17.98 秒，Faster 2.54 秒。两种构建都已运行过，缓存状态不同；仅作为本机开发反馈，不代表冷启动或部署性能承诺。
- 搜索验收发现中文锚点异常。普通产物中存在 NUL 字符，Faster 的 HTML 压缩将其替换成 U+FFFD；两种产物都影响搜索定位。与 [React 18 上游问题](https://github.com/react/react/issues/31134) 及 [Docusaurus 记录](https://github.com/facebook/docusaurus/issues/9985) 一致。
- 保留 React 18，通过原生 `ssrTemplate` 在 HTML 压缩前去除流式 SSR 额外插入的 NUL；正文文件不改。兼容代码校验模板插槽存在，避免未来升级后静默失效。新增回归测试先失败，再验证所有生成 HTML 无异常字符、全部搜索锚点都有目标。
- 搜索插件输入框原本硬编码英文 ARIA 标签，主题包装层将其与已翻译的 placeholder 同步。补齐框架中文“跟随系统”和菜单展开/收起提示。
- 完整语言名称恢复后，手机菜单在窄屏仅保留站点 Logo，避免站点名被挤成省略号；997–1199 像素桌面收紧搜索框和导航间距，英文导航保持单行。
- 最终 `npm ci`、类型检查、双语生产构建与 6 组产物测试通过。初次受限网络安装遇到 DNS 错误，获准联网后重新安装成功；构建仅有更新检查器无法写入本机配置目录的非阻断提示。
